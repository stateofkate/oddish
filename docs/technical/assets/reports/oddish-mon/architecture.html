Before: two machines per trial, one of them only waits

After: one machine per trial, and it reports on itself

How it stays safe

On purpose

  • Behaviour kept identical. Same results, same files, one extra log. No feature rode along.
  • Ramp by sample with automatic fallback, so a bad day costs one retry, not a trial.
  • Images built once per task version in a warm-up box, not inside every paid trial.
  • Restricted-network tasks got a stricter firewall on the way. A restricted task can no longer ping out, which the old path quietly allowed.
  • 5% memory headroom kept so 8 and 16 GiB tasks do not run short.

Deliberately not built

  • No shared launch host. A follow-on design that removed the per-trial launcher too was set aside on 23 Sep: it traded a known-safe per-trial process for a shared one, for about 0.5% of compute$25k a year.
  • No GPU path yet. Small prize, separate design. See the appendix.
  • No review jobs yet. Audit and QA stay on the old path until the credential handling is carried over.
  • Old path kept. It is the fallback and the only path for four categories. Deletion waits for 100% and full coverage.

Modal, the constraints we designed around

  • Work that must not be interrupted costs 3x. The watcher was that for hours. The launcher still is, for 20 seconds.
  • Docker needs a VM, and VMs cannot have GPUs. One constraint, and it is the whole GPU story.
  • Sandboxes are rate limited at creation. About 5 a second observed; 16 launches were refused in one hour at 20%. Each refusal falls back to the old path, so trials still run but the saving leaks. 10 a second needs a support request.
  • Creating a sandbox takes 16 to 39 seconds. The snapshot cache hides most of it on repeat tasks.
  • The invoice and our ledger are different things. Our ledger prices each piece with a rate card last checked in July. Percentages here are the ledger's; dollars are estimates until the two are reconciled.
